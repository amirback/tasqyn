# Tasqyn

**Краудсорс-карта паводков в реальном времени. Пилот — Уральск, ЗКО.**

**Сайт: https://tasqyn.vercel.app**

Жители отмечают уровень воды на своей улице одним нажатием. Сообщение
появляется на карте у соседей и в панели ДЧС сразу — не через сутки.

## Что уже работает

| Экран | Адрес | Что делает |
|---|---|---|
| Лендинг | `/` | Живые цифры по городу, уровень тревоги, данные по реке |
| Карта | `/map` | Метки жителей, тепловая карта, фильтры, лента |
| Сообщить | `/report` | Отправка за 4 шага: тип → глубина → место → детали |
| Мои адреса | `/alerts` | Наблюдение за домом/работой + уведомления браузера |
| Панель ДЧС | `/dashboard` | Сводка, очаги подтопления, лента, выгрузка CSV |

### Прогноз

Расход воды берётся из GloFAS в четырёх точках русла Жайыка — Оренбург, Илек,
Рубёжка и сам Уральск. Вода приходит к городу сверху, из Оренбургской области,
поэтому подъём выше по течению виден в Уральске через несколько дней: весной
2024 года паводок шёл именно так. Рядом — осадки, свежий снег и число дней с
переходом температуры через ноль (снеготаяние).

Это расчёт моделей, а не предупреждение ДЧС, и в интерфейсе так и написано.
Прямо в блоке прогноза стоят ссылки на карту гидропостов Казгидромета и на
МЧС — первоисточник всегда в одно касание.

### Норма и калибровка

У Open-Meteo есть поле `river_discharge_mean`, которое легко принять за
сезонную норму. Для прошедших дат оно равно самому расходу, поэтому
«отклонение от нормы» на нём выходило ровно 0% — цифра выглядела осмысленной,
но не значила ничего.

Настоящая норма считается скриптом `scripts/build-climatology.mjs` по 20 годам
архива GloFAS (2004–2023) и лежит в репозитории готовым файлом
`src/data/climatology.json`.

Второй урок этих данных важнее: **относительное отклонение обманывает**.
В августе расход бывает вчетверо выше медианы того же дня — и это по-прежнему
межень. Поэтому опасность меряется не перцентилем внутри дня, а распределением
**годовых пиков** реки:

| Полоса | Расход у Уральска | Что это значит |
|---|---|---|
| межень | до ~590 м³/с | обычное состояние |
| ниже пика | 590–840 | четверть лет так и не поднимается выше |
| обычный пик | 840–2250 | типичный весенний максимум |
| высокая вода | 2250–3150 | выше трёх четвертей лет |
| большой паводок | 3150+ | апрель 2024-го прошёл на 3235 |

Модель проверена по архиву: в дни катастрофы 2024 года она даёт максимальный
вклад реки, а на обычных вёснах 2006 и 2019 — нулевой. Летняя межень тревогу
не поднимает.

### Уведомления

Push доходит при закрытом браузере, а не только пока открыта вкладка.
Отправляются событийно: появилось сообщение — сразу проверяются подписки,
чьи точки попали в радиус. Отдельный планировщик не нужен.

Будим не по каждому поводу: лужа по щиколотку молчит, вода по колено и глубже,
перекрытая дорога и просьба о помощи — сообщают. Не чаще одного уведомления в
три часа на адрес, и человека не будят его же сообщением.

Приватность: чтобы уведомление дошло, сервер обязан знать, где смотреть.
Туда уходят только координаты, округлённые до ~100 м. Названия («дом», «мама»)
и точный адрес остаются в телефоне.

**Три языка:** русский, қазақша, English — переключаются в шапке.

### Как устроен продукт

- **Глубина — не в сантиметрах.** Человек в панике не мерит рулеткой, поэтому
  выбор идёт по телу: по щиколотку / по колено / по пояс / выше роста. В метры
  переводим сами.
- **Проверка соседями.** Два подтверждения — статус «подтверждено». Два
  опровержения — сообщение уходит с общей карты (но остаётся в панели ДЧС:
  фейк тоже сигнал).
- **Уровень тревоги считается прозрачно.** Расход воды в реке, отклонение от
  нормы, тренд, осадки, число и глубина сообщений — каждое слагаемое показано
  пользователю. Никакого «AI-скора» в теме, где речь идёт об эвакуации.
- **Работает без сети.** Сообщение ложится в очередь на телефоне и уходит само,
  когда связь вернётся. Это не украшение: в подтопленных районах сеть падает
  ровно тогда, когда нужнее всего.
- **Без регистрации.** Ни телефона, ни почты, ни имени. Устройство различаем
  случайным ключом в браузере. «Мои адреса» не покидают телефон вообще.
- **Не падает без WebGL.** На бюджетных Android карта может не запуститься —
  тогда сообщения показываются списком.

### Откуда берутся данные

| Источник | Что даёт | Ключ нужен? |
|---|---|---|
| [Copernicus GloFAS](https://global-flood.emergency.copernicus.eu/) через [Open-Meteo](https://open-meteo.com/) | расход воды в Жайыке + сезонная норма | нет |
| [Open-Meteo Forecast](https://open-meteo.com/) | осадки и температура на 14 дней | нет |
| [OpenFreeMap](https://openfreemap.org/) + OpenStreetMap | подложка карты | нет |
| [Nominatim](https://nominatim.org/) | адрес по координатам и поиск | нет |
| [Казгидромет](http://ecodata.kz:3838/app_dg_map_ru/) | карта гидропостов — ссылкой, без интеграции | — |

Ни один источник не требует договора или оплаты — пилот переживёт пиковый день
паводка без счёта за API.

Казгидромет намеренно не скрейпится. Открытого API у него нет: портал
data.egov.kz выдаёт ключ только через личный кабинет, а карту постов крутит
Shiny поверх websocket. Тянуть её парсером в сервис, по которому решают,
эвакуироваться ли, нельзя — сломается молча и соврёт. Поэтому даём прямую
ссылку, а не притворяемся, что интегрировались.

## Запуск на своём компьютере

Нужен [Node.js](https://nodejs.org) версии 20 или новее.

```bash
npm install     # поставить зависимости (один раз)
npm run dev     # запустить
```

Откройте **http://localhost:3000**

База данных (`data/tasqyn.db`) создастся сама. Настраивать ничего не нужно.

### Демонстрационные данные

Чтобы карта не была пустой на показе:

```bash
npm run seed          # ~55 выдуманных сообщений по районам Уральска
npm run seed:clear    # стереть всё и засеять заново
```

> Демо-сообщения помечены словом «[демо]» в комментарии.
> **Перед боевым запуском базу нужно очистить** — выдуманные точки в сервисе,
> по которому принимают решение об эвакуации, недопустимы.

### Панель ДЧС

Адрес `/dashboard`. Локально пароль по умолчанию — `tasqyn`; на боевом сайте
задан свой через переменную `DASHBOARD_PASSWORD` в Vercel.

## Публикация в интернет

**Уже опубликовано и настроено:** https://tasqyn.vercel.app — Vercel + база
Turso, метки сохраняются. Ниже — как это повторить с нуля, если понадобится.

1. Зайти на vercel.com через GitHub, нажать **Add New → Project**, выбрать
   репозиторий `tasqyn`, нажать **Deploy**.
2. Создать базу на turso.tech, скопировать оттуда URL и токен.
3. В Vercel → Settings → Environment Variables добавить:

   ```
   TURSO_DATABASE_URL = libsql://…
   TURSO_AUTH_TOKEN   = …
   DASHBOARD_PASSWORD = свой пароль
   VAPID_PUBLIC_KEY   = …   # ключи для push, см. ниже
   VAPID_PRIVATE_KEY  = …
   ```

4. Нажать **Redeploy**.

Без этих переменных приложение работает, но база лежит в `/tmp` бессерверной
функции: сообщения исчезают при перезапуске. В таком режиме сайт сам пишет об
этом на карте («демо-режим»).

Ключи Turso заданы только в переменных окружения Vercel и в репозиторий не
попадают. Локальная разработка их не видит и пишет в свой файл `data/tasqyn.db`
— так тест на компьютере не может испортить боевые данные.

---

### Ключи для push

Уведомления подписываются парой VAPID-ключей. Новую пару можно сделать так:

```bash
node -e "console.log(require('web-push').generateVAPIDKeys())"
```

Без этих переменных приложение работает, просто кнопка уведомлений не
появляется.

## Из чего собрано

- **Next.js 15** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS 4** — тема «вода и бумага», один акцентный цвет
- **MapLibre GL** — векторная карта без ключей и лимитов
- **Motion** + **Lenis** — анимации и инерционная прокрутка
- **SQLite** через `@libsql/client` — один диалект и локально, и в облаке

```
src/
  app/          страницы и API-маршруты
  components/   карта, шторка сообщения, навигация, анимации
  lib/          база, сообщения, гидрология, оценка риска, гео
  i18n/         три словаря; форма проверяется типами
scripts/seed.mjs   демо-данные
```
